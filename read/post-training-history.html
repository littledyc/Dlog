Part 1：前史：从 Pre-Training 到 Fine-Tuning

原文

重新学习概率论的同时再开一个新坑吧。如果说 Scaling Law 主导了人工智能浪潮的第一章，把大家都推上了卷更多的参数，堆更多的算力上，那么如今的第二章，在单纯继续扩大 pre-training compute 的边际收益下降，训练成本迅速上升，同时高质量数据成为约束之一之后，Post-Training 将会成为，或者应该是已经成为了十分重要的一环。从 SFT 到 Preference Optimization，再到百花齐放的 RL-Based Post-Training，再到面向 Agent 的训练，以及未来可能的 Self-Improvement 等发展，Post-Training 到底从何而起，经历了什么，现在怎么样，未来还有多少发展潜力，是一个很重要，也是我想要学习，了解，思考并投身的方向。

这篇文章大概会按照时间顺序来组织，主要会围绕 Preference 和 Reasoning 两条主线来讲……整个写作的周期可能会持续 2-3 个月，我的目标是在年底之前把这个坑填完吧，希望我能做到。

我们正在拥抱未来。

【补】 作者这句”pre-training 的边际收益下降”背后是两场著名争论，值得知道名字：

  • Kaplan scaling law（2020，OpenAI）：性能随参数量幂律提升，当时认为数据不是瓶颈。
  • Chinchilla（2022，DeepMind）：指出 GPT-3 一类模型其实训练严重不足，模型比数据大太多；算力最优配比下两者该同步增长。
  • 后续 Llama-3 用 15T tokens 又把”compute-optimal”的边界推得很宽——说明”最优”本身也在动。

作者真正想说的趋势我概括为：**堆参数的边际收益在跌，注意力转向”怎么用好已有模型”**。这也正是 Post-Training 变成主战场的原因。

在今天看来，业内对于 LLM 训练的共识，都是我们要先做 Pre-Training，再做 Post-Training。但是如果我们回看 2018 年的 NLP，大家可能不是这么想的。当时固然已经有一些通用的底座，Word2Vec、GloVe 这类 pretrained word embeddings 已经很常见，但是人们还是倾向于对每个不同的问题都重新用它们做监督训练，然后直接部署。

所以在当时，如果训练好一个模型之后，要解决另一个问题怎么办？重新训练另一个模型。

这就跟现在很不一样了，我们都知道 GPT、Claude 这样的模型已经可以做到一个模型解决很多不同领域的任务。而这种转变的萌芽，恰恰就发生在 2018 年前后。那一年几乎连续出现了三种关键路线：ELMo、ULMFiT，以及最接近今天 LLM 训练范式的 GPT-1。我们后续会逐一拆解。而年底的经典之作 BERT，更进一步证明了一个预训练模型只加很小的 task head，就可以 fine-tune 到大量完全不同的 NLP 任务上。

【补】2018 年这四篇的准确出处（考据用）：

工作出处关键数字
ELMoPeters et al., AllenAI, arXiv 1802.05365双向 BiLSTM，层间加权求和
ULMFiTHoward & Ruder (fast.ai), arXiv 1801.06146, ICML’18100 条标注数据
GPT-1Radford et al., arXiv 1806.04832117M 参数
BERTDevlin et al., arXiv 1810.04805双向 Encoder + MLM

作者说的”三种关键路线”其实对应两种世界观：**ELMo 是”抽特征喂给下游”，ULMFiT 和 GPT-1 是”直接微调模型本身”**。后者赢了，这就是今天的范式。

“风暴前夜——Semi-supervised Sequence Learning”

早在 2015 年，其实已经有人提出了先预训练 LSTM，再把参数作为 supervised task 的初始化这一条道路。作者在实验中发现这样预训练后的 LSTM 更稳定……因此已经提出了”语言模型可以不作为最终任务，而作为下游监督学习的参数预训练阶段”这一理念。

但是在当时，这一理念还受到诸多限制……其次，LSTM 本身的架构决定了它的训练存在沿序列方向的递归依赖，难以并行化，因此随着语料和模型规模增长，训练成本会越来越难以承受……

【补】 这里说的是 Dai & Le, Semi-supervised Sequence Learning, NIPS 2015（Andrew Dai 和 Quoc Le）。它历史地位重要，因为它第一次把 “LM 预训练 → 下游微调” 这条路跑通了。

作者点出的三个限制（LSTM 难并行、下游微调会灾难性遗忘、微调技术不成熟）都很准。其中”灾难性遗忘”这一条，一直延续到了今天的 LLM post-training——这也是为什么后面会有 KL 惩罚、reference model、以及各种对齐税（alignment tax）的研究。这是个很好的历史伏笔。

“初道惊雷——ELMo：Contextual Representation”

我们前文已经提到，2018 年之前已经有 Word2Vec、GloVe 这类通用的预训练词表示底座，但是局限性也很明显，他们会给每个词分配一个固定的向量……ELMo 认为一个词的表示应该是上下文化的，并且可以由一个 deep BiLM 不同层的表示的 task-specific 加权和作为最终表示……

论文还做了一个很关键的分析，它发现不同层确实学到了不同层次的信息，较低层对于 syntax 更有帮助，较高层对于 semantics 更有帮助……

【评】 ELMo 的分层结论（低层句法、高层语义）是个有效的启发式，在今天依然成立。现在看 Transformer 的 interpretability 研究（logit lens、residual stream 分析），基本都会观察到类似的分层现象。作者点出论文强调 “deep” 的原因（因为不同层真的不一样），这个细节抓得好。

“跨过遗忘——ULMFiT 与稳定 Fine-Tuning”

ULMFiT 做的事情就是在一个预训练的模型上继续 fine-tune……第一步是在大规模通用语料上训练一个 LM，第二步则是用目标任务自己的文本继续做语言模型训练，让模型适应目标领域的分布，第三步才是在上面加分类头……这已经有点今天 continued pretraining 和 SFT 分阶段适配的味道了。

……如果模型在小规模下游数据上直接大步更新，可能会忘记自己预训练阶段已经学到的通用知识……因此论文使用了一些技巧，比如不同层使用不同学习率……同时不是一开始就允许修改所有参数，而是逐渐解冻。

而 ULMFiT 最漂亮的一个结论是它可以只在很少的数据上做 fine-tune，也可以达到接近甚至超过大量监督数据从头训练的效果。ULMFiT 原论文报告只用 100 个 labeled examples 就可以匹配从头训练时使用 100 倍标注数据的性能。

【评】 这段是全 Part 1 我最想让人注意的地方。

ULMFiT 在 2018 年就发现的事情——“少量高质量数据就够”——和 2023 年 LIMA 的结论、和今天”高质量指令数据比垃圾量更重要”的共识，是同一个现象的不同年代版本。 八年过去，结论没变，变的是规模。

作者提到的”分层学习率 + 渐进解冻”现在确实不重要了，但背后的思想换了马甲还在用：今天的 LoRA 冻结主干只训低秩增量、以及各种参数高效微调，本质上都是”小心地改、别把预训练学到的弄坏”。

“范式成型——GPT-1”

ULMFiT 已经把 pre-train 到 fine-tune 这条线搭建的非常基础了。GPT-1 更重要的地方是把这套范式和 Transformer + task-agnostic architecture 结合起来。作者明确希望尽量不为不同任务修改模型本体，而是改变输入的表达方式，让同一个 Transformer 去处理不同任务。

对于不同的任务，它们之间可能有差异很大的原始结构，GPT-1 通过 task-aware input transformations 把它们统一转换成 token sequence……形成了”把任务本身文本化”的早期雏形，并且离后来的表示只差了一步，现在的模式是用户直接用自然语言表达任务，GPT-1 是人为规定了一种输入格式来表达任务。

【补】 作者这个观察很有价值，值得单独记住：

GPT-1 的 task-aware input transformation 和今天的 chat template 是同一件事。

  • GPT-1：人工设计「Translate to french: english text」这种前缀 + 分隔符
  • InstructGPT / 今天：<|system|>...<|user|>...<|assistant|>，同样是任务描述文本化

GPT-1 论文里那个 [CLS] 式的分隔符、把蕴涵/相似度/问答都拍平成序列的套路，就是今天 prompt template 的直系祖先。从”人设计输入格式”到”人用自然语言提要求”，中间隔的是几年数据和规模，不是范式革命。

在预训练阶段，GPT-1 使用了 decoder-style Transformer……论文对此还专门做了 ablation，把 Transformer 换成 LSTM 后，平均表现明显下降，而完全移除 pretraining 后下降更严重，在他们的分析中，不做预训练相对完整模型平均下降约 14.8 个百分点。

……而在我们要重点关注的 SFT 阶段，GPT-1 不仅优化 Loss，同样要求模型把语言建模做好，不希望模型 SFT 之后失去已有的语言建模能力。这和 ULMFiT 面临的问题是相通的……不过论文对此也做了 ablation，表示这个优化并非对于所有任务都有用。

我认为真正值得重点理解的也就是 Zero-Shot Behavior……

【评】 GPT-1 的 auxiliary LM loss（SFT loss + LM loss）和 ULMFiT 的抗遗忘是同一个问题的两个答案。今天这个问题叫 alignment tax / 对齐税——模型对齐后基础能力下降。

顺带一提，今天 PPO/DPO 里的 KL 惩罚项（拉住在策略模型不要离 reference model 太远）在思想上和这个 auxiliary loss 完全同源：**都是”允许你适应新目标，但不许忘了本行”**。

作者花大段讲 Zero-Shot Behavior 是对的，这是全 Part 1 最重要的一处伏笔——**GPT-1 已经隐约看到”预训练本身就带来任务能力”**，这个直觉一路通向 GPT-2 的标题。

GPT-1 的作者正是在训练中发现，即使还未进行 SFT，LM 在某些任务上的性能也会随着 pre-training 的进行而提高。对此，他们提出了一个假设……他们认为语言模型为了把 next-token prediction 做好，在训练过程中就不得不学习一些下游任务本身需要的能力。

……其意义在于 pre-training 让模型获得了一部分解决下游任务的能力，但并不能因此否定 SFT 的重要作用。我们反而可以引出一个重要的问题，如果 pre-training 已经让模型学到了通用语言表示和部分解决问题的能力，那么 post-training 到底是”继续教会模型新的能力”，还是”选择并释放模型已有的但未展现的能力”……

【评】 作者自己标出来的这个问题，就是整个 post-training 领域最核心的争议，而且到今天没有定论。

顺便说，作者这个提问本身就说明他抓到要点了：这不是历史问题，是当代问题。 下文 Part 2 讲 SFT 时他会给出自己的答案（倾向”释放”），而 Part 3 讲 RL 时会给出另一半答案。带着这个问题往下读，比顺着读收获大得多。

“旧日高潮——BERT”

年底，经典之作 BERT 再次验证了 pre-training + fine tune 范式的有效性。BERT 在文本上使用基于双向 Transformer Encoder 的 Masked Language Modeling 进行 pre-training……BERT 无疑把”预训练大规模语言模型，然后对不同下游任务做 fine tuning 适配”推成了 NLP 的主流范式……不过 BERT 的模式仍然需要对不同任务做专门的微调，离后来统一任务接口还有一定的距离。

不过，既然一个模型已经可以适配这么多任务，加之 GPT-1 已经展现出 zero-shot 能力，我们真的还有必要对每个不同的任务都去做微调吗？

【评】 作者用”我们真的还有必要对每个任务做微调吗”这一句完成了历史叙事的关键转折，手法干净。

历史事实上 BERT 赢到了 2019–2020，之后 encoder-decoder/decoder-only 和 GPT 路线靠生成能力和 in-context learning 翻了盘。BERT 的”每个任务一个微调副本”和 GPT 的”一个模型吃所有任务”，是两条范式路线的竞争，不只是架构竞争。 作者这个潜台词埋得不错。

“GPT-2：只需要预训练就够了……吗？”

（起不出来标题了）

Language Models are Unsupervised Multitask Learners，这句话是 GPT-2 论文的标题，也很好的概括了他们的核心观点……比如在采访文本中，”Q:”后面通常跟随着问题，而紧随其后的”A：”后面通常就跟随着答案。模型如果学习了足够多这样的文本，为了预测好下一个 token，就有可能需要学到”前面有了’Q:问题’之后，后面的’A:’应该跟随着答案”这样的经验。

【补】补一个关键细节，作者没提但很重要：GPT-2 论文的核心主张其实是 **”no task-specific training, no architecture changes”**——他们认为自然语言里已经隐含了无数任务的 (input, output) 对。作者讲的”Q:/A:”例子就是论文原文的论证。

这也解释了为什么 GPT-2 之后大家会转向 instruction tuning：因为”任务指示天然存在于文本中”这个假设，在真实用户身上不成立——用户不会说”Q: 中国的首都是哪里 A:”，他们只会问”中国首都是哪”。这个”预训练以为的世界”和”用户真实行为”之间的裂缝，就是 Instruction Tuning / SFT 要填的。

对此，GPT-2 诞生了。这是一个有 1.5B 参数的模型，相比 GPT-1 的 117M 增长了超过十倍，训练数据规模也增加了十倍，他们的数据来自约 8M 的网页，40G 的数据。

他们还专门训练了不同规模的模型，并观察 zero-shot performance 随模型容量增加如何改善，而他们发现的结果是这些任务上的性能随模型规模呈近似 log-linear 改善。这是一个非常重要的历史信号，GPT-2 已经发现模型的能力会随着规模增长而增长，这正是后来所有人都会跟着 Scaling Law 猛烈推进的方向。

【评】 “log-linear 改善”这个细节抓得准。这是 Scaling Law 实证化的重要一步——GPT-2 (2019) 已经在模型尺寸上扫了 range 并报告了规律的提升，Kaplan (2020) 只是把它做成了严格的形式化。

顺便纠正一个容易混淆的点：GPT-2 的 WebText 是人工从 Reddit 高赞链接抓的，做过质量筛选，不是原始 Common Crawl。这一点关系到”数据质量”叙事的起点，作者这里没展开，但”高质量数据成为约束”这个开篇判断，源头就在这里。

GPT-2 无疑已经通过 pre-training 产生了相当程度的 task-relevant behavior……不过，站在今天的角度来看，由于缺乏预训练之后的微调，GPT-2 展现出一些问题比如答非所问……GPT-2 已经通过大规模预训练学到了一定语言能力，但是不知道用户想让他干什么，因此可能在用户想要它回答问题时继续续写这个问题。这也是后来 Instruction Tuning 最重要的动机之一。

【评】 这一段是整篇 Part 1 的落点，也是全篇论证的枢纽。 请把它和 Part 2 的”为什么 SFT 有效”连起来读：

  • Part 1 这里说：模型有能力，但不知道用户要它干什么（分布不匹配）
  • Part 2 会说：SFT 做的事就是把这个分布推向”回答问题”

这两处隔了几万字，但说的是同一件事。这是我在整篇里见到的最好的一处结构呼应。

“T5：万物皆可’Text to Text’”

T5 没有提出新的架构，但是它将所有 NLP 任务统一表述为”文本到文本”的格式……不过 T5 并没有改变模型仍然需要对不同下游任务做不同适配这一点。除此之外值得一提的是，T5 的实验同样发现模型性能随着参数量的增加而持续提升，他们最终的 T5-11B 模型在多个基准上取得了 SOTA。Scaling Law 初具雏形，不过甚至还没有到最凶猛的阶段……

【补】 T5 论文全名 Exploring the Limits of Transfer Learning with a Unified Text-to-Text Transformer（Raffel et al., JMLR 2020）。它真正被后世继承的思想不是 text-to-text 格式本身，而是**”把一切任务都变成序列到序列，架构完全不动”**——这个思想上承 GPT-1 的 input transformation，下接今天所有 instruct 模型。

T5-11B 确实是当时的 SOTA，但它仍然是 multi-task fine-tune per task 的范式，所以作者说它”没改变需要适配这件事”是对的。

“GPT-3：更大！更大！更大！或许在加上一点提示……”

Language Models are Few-Shot Learners，同样的，来自 GPT-3 论文的标题。这篇 2020 年的论文被很多人认为是现代大语言模型的开端，对此我并不完全认可，我的想法会留到这部分的最后说明。

……它表明模型规模的提升不止作用于基础生成能力，也让模型利用 prompts 完成任务的能力更强。某种意义上，后者才是 GPT-3 最有意义的 scale 现象。

【评】 作者的保留意见（”GPT-3 不完全是开端”）我猜是想说现代 LLM 的起点应该算 InstructGPT/ChatGPT：让模型真正可用的是对齐，不是 few-shot 能力本身。他说明显留到 Part 末尾，但 Part 3 结尾是空的标题，所以这个判断最终没写出来。读到这里你会发现这篇”To Be Continued”卡住的正是最有料的地方。

作者说”后者才是最有意义的 scale 现象”这句很准：in-context learning 能力本身随规模涌现，而不是底子好了顺便会了。这是 GPT-3 相对 GPT-2 的真正增量。

比如我本来要让模型把”中国”翻译成”China”，但是我先给出一些例子：”美国-United States of America；日本：Japan；……”最后再给：”中国-？”模型就很有可能输出 “China”。这已经很像今天的 post-training……不过这个时候的 in-context learning 并不改变模型参数，只是临时根据少量示例改变了输出的概率分布，但是也取得了很好的解决问题的效果。

【评】 这里可以补一条硬核的来龙去脉，作者没提但极其重要：

in-context learning 为什么能给模型”临时改分布”而不改参数？

学界到现在也没有共识，主流假说有这些：

  3. 检索 + 模式匹配：其实是在训练集里找最相似片段

前言部分到这里就要告一段落了，下一部分将会出现一定的数学知识，我们将会深入了解 SFT……GPT-3 已经证明，仅仅通过在上下文中提供任务描述和少量示例，就能够让一个固定参数的模型临时表现出符合特定任务要求的行为，而 SFT 则更进一步，通过监督训练把这种”按照我们的要求完成任务”的行为稳定地写入模型参数之中。

【评】 这个过渡写得很漂亮，我给原文的衔接手法打个高分：

  • GPT-3 / ICL：不改参数，靠 context 临时改分布
  • SFT：改参数，把这个行为永久写死

同一个目标（”按我的要求做”），两种实现路径——这是理解整个 post-training 训练体系的顶层框架。 后面 PPO/DPO 所做的一切，都还是在”改参数”这条路上，只是监督信号从”一个参考输出”变成了”一个相对好坏”。

作者最后一句”比例怎么样，是决定 SFT 质量的重要因素”——这句比前面所有具体方法都重要。数据配比（domain ratio）失调导致的能力塌陷，是工业界最常见的翻车点，而且很难事后修。

有了数据以后，通常会先对数据做清洗……同时保证不同类型的数据之间的比例不要特别失衡。在这之后，我们还要将数据编码成 token 序列：

[SYSTEM] s [User] x [Assistant] y

这里是 system prompt。比如”You are a helpful AI assistant.”

就是我们的 prompt - response 对。实际训练中，模型看到的就是这样的由特殊 token 和普通 token 组成的序列。

模型在训练中仍然做 next-token prediction。这里做的是 teacher-forcing，即计算当前 token 的时候用的是真实数据，而不是模型自己前一步训练出来的数据，和预训练阶段是一样的，因此可以并行。通常我们只在 response 上计算损失，即 response-only loss……不过也存在对整个 conversation 求 loss 的，因此不算一个公认的行业标准。

至于参数更新，最经典的做法是 full-parameter fine-tuning，即所有参数都可以更新，但是现代训练也经常采用 LoRA，通过训练两个低秩矩阵作为更新的部分，也能取得很好的效果。

【补】teacher forcing 这里值得补一个它带来的核心问题，因为这是后面整个 RL 的动机之一：

exposure bias（曝光偏差）——训练时模型永远看到正确答案上文（ground truth），推理时它看到的是自己生成的上文。一旦自己生成错了，后面就全歪。SFT 完全不处理这个问题，因为训练里根本不存在”自己生成”的场景。

记住这一条，等读到 Part 3 作者自己总结的 SFT 四大不足之三”对模型自己会生成什么缺乏直接针对性”，说的就是它。这和 RL 的关系是：RL 天然在自己生成的轨迹上学习，所以没有 exposure bias。

作者说 response-only loss”不算公认的行业标准”——这句略保守了。事实是 response-only loss 就是事实标准，全 conversation 求 loss 的极少见。我猜作者这么说是因为不同开源框架的默认行为有差异，但从我看到的训练代码看，都对 assistant turn 做 mask。

为什么？

为什么这一部分主要回答为什么 SFT 有效的问题。我比较赞成的说法是 SFT 激活了模型的能力，但是不能否认 SFT 本身也可能带来新知识，但是前者是主要的原因。

一个很强的现象是，SFT 只用很少的数据，就可以在很大程度上提升模型的性能，并且甚至展现出泛化能力。LIMA 这篇研究用了 1,000 条精心筛选的 prompt-response 数据对 65B LLaMA 做普通 supervised fine-tuning，就获得了很强的 instruction-following 表现，而且还能泛化到训练中没有出现过的一些任务。FLAN 在 60 多个 instruction-formatted NLP tasks 上训练后，对未见过的 task types 的 zero-shot performance 也显著提升，并且在 25 个评测任务中的 20 个上超过了 zero-shot GPT-3 175B。

SFT 当然有可能让模型学到新的东西，但是这不太可能是主要的原因……我赞成的观点也是 SFT 激发出了模型已经拥有的能力。

具体地说，我们知道 LLM 是从概率分布之中选择输出的……对于一个未经 SFT 的 model，巴黎当然有可能在候选里面……但是模型也可能因为见过很多其他的数据，导致候选里面可能还有继续续写等操作。

当我们做了 SFT 之后，这种概率分布被改变了，SFT 会把概率分布往”回答问题”这个方向推……模型就更有可能直接输出”巴黎”。

  • Qwen/DeepSeek 的长思维链数据：这些东西预训练里根本不存在，显然不是”释放”出来的

我的判断：两边都不全对。 现在的共识更接近”分工”——

  • 行为格式、风格、指令遵循 ← 主要是释放（预训练里有大量对话文本）
  • 复杂推理、特定领域能力 ← 确实是 SFT 教进去的

而作者的”法国首都”例子选得特别好，因为它属于第一种情况（事实知识预训练里就有），所以”释放”论在他举的例子上完全成立。这不是作者论证的问题，是例子本身的偏向性。

作者后面说”LIMA 的作者也提出’SFT 更多的教会了模型如何调用这些能力生成回答’这一观点”——这句转述是准确的。

这同样指出，模型在很多情况下都知道问题的答案是什么，这样的能力就是通过大规模预训练得到的，只是没有很好的表现出来……并且模型展现出来的泛化性说明模型并不只是记住了训练数据，而是学习了训练数据背后的模式。

这也可以解释为什么 LoRA 这样的方法是有效的。模型本身就处在一个很强的参数范围里面，那么我们并不需要做太多太大的改变，只需要在某一些还不够好的方向上微调，以尽可能保留模型的大多数能力，但同时激发出其他的能力。LoRA 让模型学习两个低秩矩阵也正是”寻找在什么方向上微调”的过程。

【评】”预训练里已经有答案，只是没表现出来”这个判断，值得过一个更严格的审视。

接下来我们会讨论 SFT 的优点和不足，然后就自然衔接到 preference 这一部分。因为不得不承认 SFT 虽然很有用，但是确实没什么能讲的。

SFT 的优点其实很好总结，第一是简单稳定，因为本质上还是标准的 next-token prediction，监督学习，交叉熵损失；第二是监督信号直接……第三是数据效率高……第四是可控性强……第五是 instruction tuning 还能带来一定的 unseen-task generalization。

但它的不足才更重要，这也正是下一章 preference 线真正登场的背景。最核心的不足是，SFT 只告诉模型”一个好答案长什么样”，却没有告诉模型”在你见到的这些答案里面哪个答案谁更好”……而进一步讲，让人亲自写一个完美回答，往往比让人比较两个回答更难。

这就意味着 preference data 可能是一种更容易提供，也更贴近”优化质量差异”的监督信号。

【评】作者这条”写答案比比较答案难”的论证，是 SFT → Preference 整条逻辑链的支点，值得停下来验证一下。

它是直觉上成立、但实际有大量 OK，可是这个反例：

  • 安全性 / 有害输出判断：比较两个回答哪个更安全，人类标注者之间一致性很低，甚至比”写一个安全回答”更难
  • 创意写作 / 代码风格：哪个更好高度主观，标注间一致性（Cohen’s kappa）常常低到不可用
  • 数学/代码正确性：这个反而不需要比较，直接可以程序化验证——这正是 RLVR 出现的原因

所以**”比较更便宜”有明确适用边界**：开放式生成任务成立，客观可验证任务上比较信息反而是浪费（直接打分就行）。

作者自己在下一段就承认了这个限定，这点很诚实：

不过这里要留一个很重要的限定，preference data 并不无条件比 demonstration data 便宜或者信息更多，有些问题中比较两个答案本身就很困难，人类之间也可能存在偏好分歧，而单次”A 比 B 好”的信息实际上传达的还不如一整段高质量 demonstration 多。所以它真正的优势是，在许多开放式生成问题上，comparison 往往提供了一种更容易扩展的监督接口，而不是所谓的 Free Lunch。我们都知道世界上是 no free lunch 的。

【补】这里可以补一个作者没展开但极其重要的点：为什么”可扩展的监督接口”比”信息更多”更关键。

因为 post-training 的成本瓶颈从来不是”人类标注员有多贵”，而是人类能不能规模化地提供信号。

  • SFT 要人写完整回答 → 标注员产能有上限
  • Preference 要人选 A/B → 产能高一个数量级
  • RLVR 要程序判对错 → 产能无限，成本趋近于零

这条”监督信号成本递减”的线，就是整个 post-training 演进的内在动力。作者讲的”更可扩展”，和后面 RLVR 的爆发，是同一个逻辑的不同阶段。这篇文章写到这里停更，恰好停在整个领域下一步要爆炸的前夜。

第二个不足是 SFT 的上限很依赖 demonstration quality……第三个不足是 SFT 对模型自己会生成什么缺乏直接针对性，训练时它一直看 ground-truth trajectory，但推理时它走的是自己生成的 trajectory，如果模型容易在某些地方偏离，SFT 本身并不会直接针对这些”模型自己常犯的错误”优化。

第四个不足是 SFT 更多的是优化概率质量分布，而我们仍然可以尝试在 post-training 的时候让模型生成更好的输出，而不是只是增加好的输出的概率。

【评】这四个不足列得很漂亮，可以做个内部结构分析（这就是我在开头导读里说的”论证链”）：

不足对应的解法
只给一个好答案，不给比较→ Reward Model（Bradley–Terry）
上限受限于 demo 质量→ 用模型自己生成候选 + 人类比较
不针对模型自己的错误→ RL：在自己生成的轨迹上学

这张表是整篇 Part 2 → Part 3 的接口。 作者写四个不足不是为了凑数，每个都精确对应后面一节。看懂这一层，这篇文章的组织能力就看得见了。

“第三个不足”就是我在上面批注里提到的 exposure bias——作者用大白话（”训练看 ground-truth，推理走自己的”）讲清楚了同一件事，这个表述比我上面引的术语更容易懂，原文这里写得好。

Part 3：Preference

原文

从 Demonstration 到 Preference：为什么我们需要比较

书接上回，SFT 固然已经很好……但是当我们提供数据的时候，我们发现很难写出一个唯一的标准回答，或者说这样的回答根本就不存在，但是比较哪个回答更好往往更容易。因此我们的想法自然地变成了，在模型已经学会怎么回答问题之后，让它回答得更好。而”怎么让模型回答得更好”，自然就是要让模型学习那些更好的回答。这就是我们为什么需要 Preference，以及它和 SFT 最本质的区别。一个提供一个参考答案，一个提供一个偏好关系。一个让模型模仿回答，一个告诉模型哪个更好。

我们当然可以自己生产数据。比如我们希望模型回答的详细，就写一点简略回答 vs 详细回答的样本……不仅仅可以自己写，现在我们还可以让模型生成数据，然后我们评价哪一个更好……但是在这里，我们可以更多地让模型自己承担生成答案，人类评价这个过程，这也就是后来 RLHF 所利用的分工。

同时，由于我们可以让模型自己生成答案候选，而我们通常关心的也正是模型自己会输出什么，于是监督信号就开始直接围绕模型自己的输出建立，这也是一个优势。

回顾一下，现在我们手上拥有的是一大堆数据：

我们现在只知道一个排序关系，怎么把它们转化成训练信号呢？

一个自然的想法是我们给更好的答案打分 1，给不好的答案打分 0，让模型去学习。但是我们这样实际只训练了一个分类器。或许给它两个答案，它能判断哪个更好，但是它其实没有办法评价某一个单独的答案”到底怎么样”。而后者是相当重要的。如果以后我们希望模型自己生成答案——打分——优化，即我们今天熟知的强化学习，那么一个好的打分函数是必不可少的。

【评】这一节有一处极其重要的转折，作者的铺垫做得非常好，值得标出来。

他把问题从”怎么把排序变成训练信号”逼到了死角：

我的总评

这篇好在哪。 三点：

  1. 论证链完整：每个新概念的出场动机都交代了。从”我只会给一个好答案”到”我要比较”，从”只有排序”到”我要打分函数”，从”有分数”到”我要改策略”，从”方差太大”到”我要降方差”——读者永远知道”为什么需要这个东西”。
  2. 数学是完整的：从 SFT 的 CE 到 BT 的 sigmoid，从 log-derivative trick 到 policy improvement theorem 的证明，从 SARSA/Q-learning 到 GAE，关键推导一个没跳。很多教程讲 RLHF 是讲故事，这篇是讲数学。
  3. 历史感是准的：2018 四篇的定位、GPT-2/GPT-3 的承接、ULMFiT 和 LIMA 的呼应，时间线和因果都没错。

缺什么。 也是三点：

  1. 停在 2023 年以前：DPO（2023.5）、KTO、ORPO、GRPO（2024）、RLVR/R1（2025）、一切 agent 训练，统统没有。按今天的标准，这篇覆盖的是”RLHF 1.0”，而工业界已经在”RL 2.0”。
  2. 工程细节偏少：KL 惩罚怎么写、PPO 的 clip 到底 clip 什么、RM 怎么防过拟合、instruct 数据配比——这些决定成败的东西都没展开。不过作者定位是”讲原理”，这不算错。
  3. 个别概念表述可再严谨：那处”贪心”的用词（正文已校）、response-only loss 的行业地位（正文已补）。
